## 可以做、還沒做（要真的加分才做）

- 簡體書一鍵轉繁體（匯入的 TXT／EPUB 很多是簡體）。
- 直排（由右到左）排版。
- 音軌離線下載（現在要連網才能播）。

## 已知問題

- 上線前檢查用的是 Chromium，沒有在真的 iPhone 上測過：仿真翻頁的手感、鎖屏播放、加入主畫面後的行為，要等痞子葳回報。
- 音軌放在 Pages 的 repo 裡，一章 6～12 MB；錄到上百章會逼近 1 GB 上限，到時候要搬（另一個 repo 的 Pages，或 Releases）。

## 搬舊章節的方法（2026-11-11 試出來的）

舊章節只留在舊對話的工具呼叫裡（當時用 Write 寫檔、Edit 改稿），檔案本身已經不在。

- **主對話不要自己重打章節內文**：長篇逐字輸出會被安全機制擋下，整段回覆被收回、做到一半的事也會從對話裡消失（當天發生兩次）。
- 做法：開幾個分身（省額度的模型即可），每個負責舊對話的一段輪次，用 `read_conversation` 一次讀一兩輪：
  Write 的內容原樣存成 `NNN.t<輪次>.md`；同一輪的 Edit 照順序套上；後面輪次回頭改前面章節的 Edit 另外存成 old／new 兩個檔，全部做完再照輪次套；會改章節的 shell 指令（sed 之類）抄進紀錄，由主對話判斷。
  工具結果夠大時會被存成檔，分身可以直接用程式從那個檔取出 Write 的內容，比重打更準。
- 組裝、套後續修改、上架全部用腳本做，只印字數和「一不一樣」，不要把內文印出來。
- 驗證：同一章有兩份獨立副本時逐字比對（《朕自邊關來》有 9 章這樣比過，全部一致）；每章跑引號成對、半形標點檢查（`shelf.py check`）。
- 工作檔一律放 repo 外面（這個 repo 是公開的）。
